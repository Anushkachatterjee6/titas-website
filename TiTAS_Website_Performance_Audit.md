# TiTAS Website Performance Audit

**Website:** https://titaspdw.com/ (https://www.titaspdw.com/)
**Audit date:** 14 October 2026
**Prepared for:** SUJIT AQUA ENTERPRISE (TiTAS packaged drinking water)

---

## 1. Purpose and scope

This report covers a performance audit of the live TiTAS website and a first round of code-level optimisations. It records the original baseline measurements, explains the root causes identified, documents exactly what was changed, and states what has and has not been verified so far.

**Important distinction used throughout this report:** the figures in Section 2 are **live-site measurements** taken from the deployed website at https://titaspdw.com/. The figures in Section 6 are **local build verifications** — checks run against a local copy of the production build, confirming the code changes behave as intended before deployment. The two are not the same thing, and the local verification does **not** by itself prove the live site's PageSpeed score has changed. The live site has not been re-tested since these changes were made, and no code has been deployed.

## 3. Root-cause findings (independently confirmed)

To understand *why* the scores above were low, the live site's HTML and assets were inspected directly.

### 3.1 Excessive image preloading (26 preload tags)
The live homepage's `<head>` contained **26** `<link rel="preload" as="image">` tags. Preloading tells the browser to fetch an image immediately, at high priority — competing directly with the resources needed for the Largest Contentful Paint.

Investigation of the site's source traced this to the build tool's automatic preload behaviour: images that are statically imported into a JavaScript module reachable from the homepage's main code bundle get preloaded automatically, regardless of whether they are visible on screen when the page loads. In this case, 20 decorative images belonging to three separate homepage sections — two of which render well below the fold — were bundled into a single shared module, causing all 20 to be preloaded on every homepage visit, whether or not the visitor ever scrolls to see them.

This is the leading explanation for the very high Largest Contentful Paint figures (21.6 s mobile, 3.9 s desktop) and is consistent with the ~53 MiB image-delivery savings PageSpeed Insights reported.

### 3.2 Oversized image assets
Direct measurement of individual image files on the live site found multiple decorative PNG exports in the 2–3 MB range each, for example:
- `source-3d...png` — 2.22 MB
- `purification-3d...png` — 2.38 MB
- `quality-3d...png` — 2.16 MB
- `bottle-3d...png` — 1.97 MB
- `delivery-3d...png` — 2.57 MB
- `network-center-splash...png` — 3.19 MB
- `TiTAS Water Marketplace Splash Showcase...png` — 2.37 MB

These are uncompressed exports rather than web-optimised images, and multiple copies are being downloaded on every homepage visit (see 3.1). **Image compression was explicitly out of scope for this round of work** and has not yet been addressed — see Section 7.

### 3.3 Missing explicit image dimensions
All 60 `<img>` elements found on the live homepage were missing `width` and `height` attributes. Without these, the browser cannot reserve layout space for an image before it loads, which can contribute to layout instability and is flagged directly by PageSpeed Insights as a best-practice issue.

### 3.4 Render-blocking Google Fonts stylesheet
The site loaded its Google Fonts stylesheet (four font families used throughout the site) using a standard `<link rel="stylesheet">` tag. This is a render-blocking pattern: the browser must download and parse the stylesheet before it can finish rendering text on the page, contributing to the render-blocking request time reported by PageSpeed Insights (~580 ms mobile, ~140 ms desktop).

## 4. Optimisations implemented

Three targeted, code-level fixes were implemented in this round, within the following constraints agreed in advance: preserve the existing visual design, branding, layout, text, navigation, functionality, and animations; no changes to pricing, checkout, authentication, Supabase configuration, or payment functionality; no image compression or removal in this round; no commits, pushes, or deployments.

### 4.1 Code-splitting the three homepage visual components
The single shared module responsible for the 20 preloaded decorative images was split into three independent components, each loaded only when needed rather than bundled together:

- `src/components/site/WaterJourneyVisual.tsx`
- `src/components/site/ServicesNetworkVisual.tsx`
- `src/components/site/OrderingFlowVisual.tsx`

These replace the previous single `MotionAssets.tsx` file (removed). In `src/routes/index.tsx`, each component is now loaded on demand using React's standard code-splitting mechanism (`React.lazy` with `Suspense`), with a correctly-sized placeholder shown while each component loads so that no blank space or layout jump occurs. All existing animations, visual styling, and section behaviour were preserved exactly as before.

### 4.2 Adding explicit image dimensions
Real, measured image dimensions (not estimated or guessed) were added as `width` and `height` attributes across the site's most widely used image components:

- The 19 images across the three newly split visual components (4.1).
- The 5 slides in the homepage hero slideshow (`src/components/site/HeroSlideshow.tsx`, `src/data/images.ts`).
- The 8 hero images used across inner-page headers sitewide (`src/components/site/PageHero.tsx`, `src/data/heroImages.ts`).
- The shared brand logo and wordmark used in the navigation bar and footer on every page (`src/components/site/Logo.tsx`, `src/components/site/TiTASWordmark.tsx`).
- Two additional homepage-specific images (the mineral composition graphic and a brand mark instance in `src/routes/index.tsx`).

Responsive sizing and existing image cropping/fit behaviour were preserved; the new attributes only tell the browser the image's natural proportions in advance.

### 4.3 Non-blocking Google Fonts loading
The Google Fonts stylesheet (`src/routes/__root.tsx`) was changed from a standard blocking `<link rel="stylesheet">` to a preload-and-swap pattern: the stylesheet is preloaded at a lower priority and only applied once ready, with a `<noscript>` fallback included for visitors with JavaScript disabled. The same four font families and weights already in use were preserved exactly, including the existing `display=swap` setting, so there is no change to typography and no new risk of a flash of invisible text.

## 5. Why image compression was not included in this round

Compressing or re-exporting the oversized PNG assets identified in Section 3.2 is a meaningful next step, but it was deliberately kept out of this round of work at the client's request, to be carried out as a separate phase. No images were compressed, replaced, or deleted in this round.

## 7. Outstanding work

The following items are known and intentionally not addressed in this round:

1. **12 remaining homepage images without explicit dimensions** — these are the product thumbnail cards and a set of lifestyle/gallery photographs on the homepage; they were not part of the components touched in this round.
2. **Images on other pages of the site** — the dimension fixes in this round focused on components shared across the whole site (navigation, footer, page headers) and the homepage's specific sections; a full page-by-page audit of every remaining image on every route has not yet been carried out.
3. **Image compression** — the oversized PNG assets identified in Section 3.2 have not been compressed, converted to a more efficient format, or resized. This remains the largest single opportunity identified and is planned as a separate phase.
4. **Live PageSpeed Insights retesting** — the scores in Section 2 remain the most recent live measurement. No new live score exists yet. A fresh PageSpeed Insights (or equivalent) run against the deployed site, after these changes are deployed, is required before any improvement can be confirmed or reported.

No performance scores, loading times, savings, or business outcomes are claimed for the live site in this report beyond what is stated in Section 2. The live site has not yet been changed.

---

## 8. Summary

The original PageSpeed Insights baseline (Section 2) reflects the live site as it stood on 14 October 2026. Direct inspection of that live site confirmed four concrete, addressable causes: excessive image preloading, oversized uncompressed image assets, missing image dimensions, and a render-blocking fonts stylesheet (Section 3). Three of these four causes have now been addressed in code — preload behaviour and missing dimensions substantially, and font loading fully — and verified against a local copy of the production build (Section 6). Image compression remains outstanding as a separate, larger piece of work, and the live site has not yet been re-measured, since nothing has been deployed. The next concrete step is deployment followed by a fresh PageSpeed Insights run to confirm real-world impact.
